# 材料、项目与语音

这些功能复用当前微信通道。收集、查看、归类和勾选完成由程序直接处理；提交总结、行动清单或文献研究才调用模型。

## 连续收集

```text
开始收集 导师修改意见
（连续发送文字、图片、录音或文件）
发完了：提取行动清单，每一条附原文依据
```

单独发送“发完了”只保存。之后使用“处理材料 导师修改意见：要求”。“取消收集”保留草稿，“继续收集 名称”恢复未提交的材料。收集期间仍可以查任务、切换会话和创建项目；材料保持绑定开始收集时的会话。

在管理页面的“材料与项目”中，可粘贴原文、填写发言人、追加文件、归入项目、选择处理会话或提交资料库。普通文件保留7天，加入材料包时另存原件，材料和行动状态保存在SQLite中。每个包最多1000条来源、2 MiB文本、15个不同附件；第16个任务附件用于来源清单。单条来源文本最多256 KiB。每个用户最多128个材料包和64个项目。空间不足会明确失败，已有资料保留。

## 引用操作

引用助手的任务结果后发送：

- `停止这个`：只请求停止引用对应任务。
- `补发这个`：只补发该任务未被接口接收的附件。
- `重试这个`：重试失败或已停止任务。
- 普通分析要求：进入引用对应会话，不改变当前会话选择。

引用材料确认消息后，可发送“加入会话 编号”调整未提交材料的处理会话，或“处理这份材料：要求”。回答选项仍引用原问题。绑定只信任本用户的已记录消息，不从转发文字中推测任务身份。

## 项目和行动清单

```text
创建项目 毕业论文
加入项目 毕业论文
项目列表
项目状态 毕业论文
行动清单 导师修改意见
收录材料到 <材料短ID> 图学习
```

项目关联会话、材料、任务和结果；归类不会自动移动执行目录。行动任务生成Markdown和JSON。工作台只有在来源编号存在、摘录逐字匹配原文时才导入可勾选行动清单；无法核验的输出仍保留在任务结果中，并显示原因。图片中的文字没有可核验原文时，不会假装已通过核验。勾选状态不会因刷新或重新导入丢失。

资料提交使用既有检索、方法整理、自动分类和综述版本流程，一篇论文涉及多个类别时更新全部相关综述；隧道中断时保留本地草稿等待恢复。

## 等待问题和发送状态

等待人类回答的任务释放执行名额，同时保持租约；全部问题回答后先等待执行空位再恢复。执行并发仍为`max_concurrent_tasks`（默认4），额外等待上限为`max_waiting_tasks`（默认8，范围1–32）。等待任务的进程仍消耗少量内存，同一会话的下一条任务继续排队。

工作台显示正文和各附件的接口接收状态。这不是手机已读回执。原始结果始终保留在任务页；补发只处理尚未接收的附件，普通新消息不会触发旧图片补发。

## 本地CPU转写

安装说明见[转写引擎](../deploy/transcription/README.md)。微信语音、标准录音和视频附件可先转写再处理，保留原件和带起止时间的JSON/TXT。引擎固定CPU、int8、4线程；无额外转写API费用。识别结果可能有误，静音明确返回没有语音。解码、模型或转写失败会返回任务错误，不虚构识别内容。

## 个人微信候选通道（需真实验收）

Go个人账号适配器基于[openwechat v1.4.10](https://github.com/eatmoreapple/openwechat)。登录资格由微信决定，不能保证每个账号都可以使用；当前iLink服务默认保持。

1. 在私有目录运行`wechat-personal --cookie <绝对路径>`，使用备用账号扫码，并查看联系人。
2. 在该账号给操作者设置唯一备注。复制一份独立的接收状态文件，候选Relay使用独立状态路径；验收时绑定原owner别名，但不要同时连接同一队列运行两个Relay。
3. 候选配置设`transport: "personal"`，填写`personal_wechat`的`cookie_path`、`root`、`friend_remark`、`owner_alias`。不允许首位发言者自动成为管理员。
4. 实测单条和合并转发、ZIP、引用、重连和主动结果；全部通过后才切换正式入口。

合并卡片解析保留顺序、发言人、时间和缺失标记。卡片中仅有附件描述时，不能凭描述下载原件；须单独提供文件。收到转发会先保存为材料，不会把别人说的话当执行授权。
