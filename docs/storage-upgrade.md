# SQLite 存储升级

Relay 与 Worker 应一起升级。部署前取得空闲维护租约、停止对应服务并备份程序与元数据目录；正在运行的任务应结束后再更换 Worker。无需更改服务器隧道、模型目录、账号或私有 Key。

首次打开存储时自动迁移已有 JSON，任务导入在一个事务内完成；无效记录会中止导入。任务目录生成 `tasks.sqlite`，设置、会话和文件索引使用原路径加 `.sqlite`，引用索引使用专用表，Worker 原生线程映射也自动迁移。原 JSON 保留，迁移标记防止重启时用旧记录覆盖新状态。

任务历史不再整体常驻内存。最近任务、执行队列和引用通过查询读取，批量遍历每页 64 条。小型会话、设置和文件索引仍有原有条数边界并会缓存；图片、附件、模型检查点和完整运行日志仍是磁盘文件。数据库使用 WAL、5 秒忙等待、完整同步及每连接约 2 MiB 页面缓存。

## 迁移检查

对停止服务后的**元数据副本**执行，不能将副本导回运行中的服务：

```sh
go build -mod=vendor -o bin/storageprobe ./cmd/storageprobe
bin/storageprobe -jobs /private/copied-jobs -mode preflight
```

核对任务数量、ID、会话、模型、原生线程映射及附件引用。未指定推理强度的旧记录迁移为历史默认值 `high`。启动后检查私有 `/health` 和 `/maintenance/idle`、SQLite `PRAGMA quick_check`、HTTPS 结果页及微信回传收据。

## 备份和回退

WAL 模式下不要只复制一个正在写入的 `.sqlite` 文件；使用 SQLite 在线备份接口，或停服务后完整复制数据库及其附属文件。凭据与内容均属私有数据，不提交到仓库。

回退前停服务并导出最新任务状态：

```sh
bin/storageprobe -jobs /private/jobs -mode export
```

此命令将当前任务表导出为同目录 JSON，供旧版读取；它不导出其他存储。会话、设置、线程与文件索引需分别导出其 `documents` 表中的 `state`；引用索引需按旧版格式导出。用户偏好及定时计划只由新版支持。不能直接恢复迁移前 JSON，否则会丢失升级后的变化。完成导出、备份和核验后再切换旧程序。

## 验证范围

回归测试覆盖任务认领、并发、租约、提问、补充、进展、回传、会话、设置、文件和引用；新增测试检查原子迁移、拒绝重复导入、偏好隔离、计划去重与取消。

合成内存对照使用 1000 条任务，每条 32 KiB 进展，测量历史存储保留的 Go 堆；它不能代表进程总内存、训练内存或显存变化。训练断点恢复与任意程序暂停仍需对应应用支持。
