# 研究知识树与校园应用

微信发送 `知识树`，打开管理页选择“知识树”。领域 → 大方向 → 类别 → 子问题 → 方法 → 局限 → 候选研究方向，逐层展开。点击节点查看原文片段、阅读范围、跨类别联系和最小实验。

- `研究方向 类别`：查询已有候选方向，不调用 AI。
- `更新知识树 类别`：使用 gpt-6.1-sol 整理指定类别。省略类别更新所有待整理分支。
- 新论文、分类调整、删除或恢复会使所有关联类别的综述与知识树待更新；旧依据过期时，当前页面先显示最新文献索引，不继续展示旧方向。
- 手工名称、置顶、笔记和个人 idea 独立保存。自动整理不写这些字段。
- 历史版本可回看与导出。候选方向可单独创建研究任务，当前微信会话保持不变。

候选假设不代表已经证明的新颖性。库内近邻需要补查外部文献；metadata_only 文献只能作为待读索引。证据验证确认片段确实出现于已观察文本，不等于科学结论已被证明。

分析输入提供按资料与来源绑定的原文目录。模型选择证据编号，程序填入对应的连续原文并再次校验，避免生成过程中翻译、重写或拼接引用。找不到原文依据的节点不能发布；历史阶段中已经正确引用的片段仍可验证后沿用。

## 校园应用

管理页 → 校园应用 → 输入名称和 `127.0.0.1:端口`（也接受完整 http:// 地址）→ 检测并生成链接。应用在校园服务器运行，阿里云复用现有私有通道转发。页面与 API 使用访问 key 和管理页登录验证；注册、检测、停止转发不调用 AI。

访问路径：`/wechat-files/manage/apps/<应用ID>/`。首次打开输入访问 key；验证后会同时建立当前浏览器的管理页登录。仅输入 `127.0.0.1`、`localhost` 或其完整 http:// 地址时，若只有一个已登记应用会沿用其地址；存在多个或没有已登记应用时要求补充端口。应用端口或路径改变时，按卡片上的“修改地址”保存新地址，应用 ID 与旧访问链接保持不变，修改前会检测新地址并拒绝与其他已登记应用冲突。停止转发只撤销访问路径，不删除程序或数据库。

根页面遇到暂时的 502/503 时显示恢复提示并每 5 秒重试，API 错误响应保留原状。路径适配会保留 JavaScript 拼接地址的后半段、split/join 的斜线和已适配路径，避免升级后请求地址出现重复前缀。

目前支持校园本机 HTTP Web 应用（含 localhost / IPv6 回环），转发 GET/HEAD/POST/PUT/PATCH/DELETE 和同源 WebSocket。常见 HTML/JavaScript/CSS 根路径引用和相对跳转会适配到应用路径，应用 Cookie 按应用ID独立限定名称与路径。复杂动态路径、Service Worker 或需要域名根目录的框架，应配置应用自身的 base URL 后再接入；这不等于支持任意软件协议。已有应用需持续运行，可用 systemd 用户服务托管。

## 数据与迁移

SQLite 增加 `knowledge_branches`、`knowledge_versions`、`knowledge_nodes`、`knowledge_evidence`、`knowledge_links`、`knowledge_annotations`、`campus_apps`；保留原有表。发布原子检查资料修订、综述版本和树版本。每个真实论文记录可以引用于多个类别，不复制原文。

维护上线先取得空闲租约，再做 SQLite 一致性备份、切换 Worker/Relay、核验配置与通道；失败回退旧二进制。

## 页面访问 key

所有 `/wechat-files/` 下的任务、结果、上传、账号上传、进度、管理和校园应用页面需要访问 key；原有签名和文件凭证继续校验。key 不写入 URL，登录 Cookie 使用 Secure、HttpOnly 和 SameSite=Strict，服务端逐次检查撤销状态与有效期。

长期 key 由密码学随机数生成 256 位随机值，首次启用后发送到主人微信。数据库保存校验哈希和加密的 key 原文；发送失败时保存加密待发送记录，微信接口接受后清除待发送记录。key 不进入引用缓存、任务提示或 AI。原文使用 AES-GCM 加密，仅长期 key 的管理员登录可以按“显示 key”查看或复制；临时 key 即使允许修改，也不能管理或读取其他 key。

管理页 → 访问 key，可以生成 1 分钟至 7 天的临时 key，限制页面路径并选择只读或允许修改；也可以显示或隐藏原文、复制 key、撤销临时 key、重置长期 key。以 `/` 结尾的范围允许该目录及下级路径，其他范围只允许完全匹配的页面。临时 key 不替代下载链接本身的到期时间。

从旧的仅哈希版本更新后，原 key 继续有效。使用原 key 登录一次会补充加密保存，随后可以显示原文，无需强制轮换。登录表单使用同源请求提交，并保留来源验证；登录页的 Referrer-Policy 为 same-origin，其余页面不发送 Referer。

只读 key 允许页面和原生资料查询，拒绝上传、任务执行、编辑、账户操作和 WebSocket。第三方校园应用本身应当遵循 GET 不修改数据的约定。长期 key 重置立即使旧 key 及其浏览器登录失效，临时 key 按独立有效期继续有效。

私有运维 `/workspace/grant` 保持 Bearer 认证，附加访问会话 Cookie 与有效期 60 秒的一次性浏览器登录入口。这个接口不会返回长期 key 原文。

## 上线验收（2026-10-12）

- `go test ./...`、`go vet ./...` 与三个新增脚本的语法检查通过。
- 真实 HTTPS 验证应用页面、静态资源和项目 API，临时修改项目阶段后恢复原值。
- 未登录的应用与任务页返回 401；范围外访问、只读 key 修改、跨来源登录返回 403；撤销临时 key 后其现有登录立即失效。
- 临时 key 即使允许修改，也不能显示长期 key 或创建其他 key。管理员显示结果与新生成的 key 在内存中核对一致，不写验收日志。
- 浏览器验收登录错误提示、管理页面登录、key 显示与隐藏、知识树筛选、节点详情和应用页面切换；390px 手机尺寸无横向溢出。
- 长期 key 重置后，新 key 登录成功、旧 key 失效，并核对微信接口已接收发送。接口接收不代表手机已读。

知识树按类别在后台生成，当前文献索引始终可查询。完成的分支显示版本和候选方向，失败分支保留资料并给出重试入口；不能将“待整理”索引视为已经完成的方法与研究方向分析。

托管研究写作应用使用 systemd 用户服务的 Restart=always；正常结束的进程也会重启，明确执行 systemctl stop 则仍会停止。升级应使用 systemctl --user restart，并保持端口及数据目录。该应用的后端文件监测在语法检查通过后重启服务，避免新前端与旧后端不一致；这不代表其他新登记程序自动拥有启动命令。

微信消息直接携带或引用完整网页访问 key 时，原生处理器拒绝将它作为 AI 任务处理，避免密钥进入新任务与模型上下文。
