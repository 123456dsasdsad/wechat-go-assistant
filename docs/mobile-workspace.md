# 手机工作台与训练

## 工作台

微信发送“管理页面”，进入短期验证链接后收藏 `/wechat-files/manage/`。验证信息保存在 Secure、HttpOnly、SameSite=Strict 的设备 Cookie 中，有效期 30 天；退出立即撤销。跨来源写入被拒绝。账号导入仍使用独立的短期入口，不在页面返回密钥。

已有有效登录的浏览器再次打开验证链接时复用原凭证，不额外创建设备登录，也不延长原有效期。设备凭证与临时上传/管理链接合计最多 128 条，过期记录在生成新链接时清理；已有凭证不因新链接生成而失效。工作台“指令查询”可按功能分类、搜索关键词并复制示例，查询不会创建 AI 任务。

任务页可以停止指定任务、重试失败任务、补发结果、回答 AI 提问、查看过程与原件。不同会话共享 Worker 的并发池，同一会话依次执行。任务列表最多显示最近 40 条，搜索可匹配历史任务；微信编号菜单最多 20 条，编号 10 分钟有效。

会话设置包括模型、推理强度、项目目录、偏好和预算。设置只影响后续任务。项目目录是 Worker `work_root/projects/` 下的相对路径；留空继续使用原会话目录。请在开始项目时选择目录，已有文件不会因改目录自动搬迁。偏好会传给 AI，因此不应填写凭据。

文件中心采用 4 MiB 分片。断网或刷新后重新选择同名、同大小、同修改时间的文件，从服务器确认的偏移继续。上传完成后校验内容哈希，至多选择 4 个输入文件创建一个任务。没有固定总字节限制，但暂存与最终入库需要磁盘余量，并预留 512 MiB；输入文件与暂存记录保留 7 天，数量各有限制。运行中的输入文件不能删除。

模板默认包含审查代码、运行项目、分析数据、训练出图。`{{内容}}` 替换成任务要求；没有占位符时将要求追加在末尾。模板仅作指令文本，不自动安装项目依赖。

## 训练接入

托管训练需要 Linux 和用户级 systemd。Worker 的服务环境需要 `XDG_RUNTIME_DIR` 与 `DBUS_SESSION_BUS_ADDRESS`，并启用用户 lingering。训练单元独立于 Worker，重启 Worker 不终止训练；本机重启后需检查状态并恢复，不承诺自动续跑。

AI 为支持的训练任务在本次任务目录创建 `training-control.json`。也可由管理员准备：

```json
{
  "enabled": true,
  "argv": ["/path/to/venv/bin/python", "train.py", "--epochs", "200"],
  "resume_argv": ["/path/to/venv/bin/python", "train.py", "--epochs", "200", "--resume", "checkpoint.pt"],
  "checkpoint": "checkpoint.pt",
  "progress_file": "training-progress.json"
}
```

命令使用参数数组，执行目录为本次任务目录；脚本与依赖必须实际存在。Worker 每 3 秒发现声明，使用自身二进制创建 `campus-training-<任务ID>` 用户服务。不要同时手动启动同一训练。相对文件路径拒绝越界和逃逸链接。未声明恢复命令或没有真实检查点时，页面不提供恢复按钮。

脚本应以临时文件加重命名的方式更新进度，格式如下：

```json
{"epoch": 25, "total": 200, "loss": 0.042}
```

每秒采样训练主进程，CPU 表示自启动以来平均使用率，多核可超过 100%；内存为主进程 RSS，不包含子进程汇总。轮次与 loss 来自脚本，缺失时无可信训练百分比。停止发送 SIGTERM，10 秒未退出则终止进程组；需要脚本自行实现检查点保存。恢复命令从已保存的检查点运行，不重新调用模型。日志保存在任务目录的 `training.log`。

训练结束时读取现有 `outputs/manifest.json`，格式见项目原件输出约定。产物身份被冻结、独立补传，并在任务页显示；原 AI 结果和附件传输完成后才接受训练产物。托管模式不是任意训练代码的自动断点适配器。

## 用量与恢复

新任务记录 Codex 报告的真实用量。app-server 使用当前线程、当前轮次事件与累计差值；旧会话首次升级后缺少累计基线时，第一轮可能显示“不可用”，之后保存基线。没有上报的数据不记作零。

美元值按仓库已知的标准 API 单价估算，未知型号/缓存写入价格不计价，并显示覆盖情况；它不代表订阅账单。预算是会话累计提醒阈值，在有已知价格的任务完成后检查，不实时中断模型或训练。

Worker 在传输前保存本地 SQLite outbox、完成记录和文件哈希。文字先提交，附件由最多两个补传执行位恢复；进程重启不重新调用 AI。上传期间文件不能被后续代码修改。收到新问题后，旧任务尚未发送的附件保持暂停，可打开原任务下载或明确补发；微信拒绝消息时仍不能保证主动送达。

## 升级与备份

两端程序必须一起升级。通过私有维护接口取得空闲租约，再停止所属 Relay/Worker，备份程序、配置、微信状态、所有 SQLite 文件与旁路文件、文件目录、Worker 会话映射和任务目录。运行中备份 SQLite 必须使用 backup API；离线复制时保留 WAL，不能只复制主数据库。

新增数据包含 Relay 的 `templates.json.sqlite`、文件目录下 `chunks/`，Worker 的 `training-index.json.sqlite` 与 `outbox/`。恢复需要文件与元数据一起恢复。回滚旧程序可能丢弃新增字段，因此有新任务后应优先修复新版；需要完整回退时使用同一时点的完整备份，并明确处理回退后新增的数据。私有 API、配置和数据不得放入公共 GitHub。
